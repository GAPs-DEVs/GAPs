# 프로젝트 벤치마크

현재는 화면 성능만 평가합니다. `app.main`의 일반 실행 흐름에 시간 기록을 추가하는 선택 기능입니다. 영상 처리 알고리즘, 카메라 워커, 악보 선택 흐름, 메인 창 크기, 영상 위젯의 크기 정책과 렌더링은 메인 앱 것을 그대로 사용합니다.

## 실행

프로젝트 루트에서 실행합니다.

```bash
uv run python -m app.main --benchmark-screen --camera 0 --duration 30 --label current-normal-run1
```

기존 명령도 같은 `app.main` 진입점을 호출합니다.

```bash
uv run python -m benchmark.screen --camera 0 --duration 30 --label current-normal-run1
```

`--benchmark-screen` 없이 메인 앱을 실행하면 측정 설정창·타이머·기록 수집기를 만들지 않습니다. `--model`, `--score-json`, `--camera-calibration`도 메인 앱과 같은 옵션입니다.

## 측정 방법

1. 처음 열리는 측정 설정창에서 시간을 정합니다. 기본 30초, 범위는 1~600초입니다. 설정창을 닫아도 **F8**로 다시 열 수 있습니다.
2. 평소와 같이 악보를 선택하고 연습 화면에서 카메라를 시작합니다. 모델·카메라 준비와 필요한 지판 맞추기를 마칩니다.
3. 메인 창 크기와 영상 크기를 비교할 조건에 맞춥니다. **F9** 또는 설정창의 **시간 지정 측정 시작**을 누릅니다.
4. 설정창이 숨겨지고 새 측정이 시작됩니다. 남은 시간은 메인 창 제목에 1초마다 표시합니다. 측정 중에는 통계표·그래프를 갱신하지 않습니다.
5. 지정 시간이 끝나면 수집을 멈추고 통계를 계산한 뒤 자동 저장합니다. 설정창에 결과와 저장 경로가 표시됩니다. 영상은 계속 실행되지만 종료된 결과에 포함되지 않습니다.
6. 다시 F9를 누르면 새 측정을 시작합니다. 이전 기록은 새 측정에 합산하지 않습니다.

측정 중 F9를 누르거나 F8로 설정창을 열면 `cancelled`, 카메라 종료·지판 맞추기·앱 종료는 `interrupted`로 부분 결과를 저장합니다. 영상 표시 영역의 크기가 바뀌면 `resized`로 종료하여 서로 다른 렌더링 크기가 한 결과에 섞이지 않게 합니다. 정상 종료 상태는 `completed`입니다.

시작 버튼부터의 실제 경과 시간(monotonic clock)을 사용합니다. 화면 갱신이 멈춘 시간도 제한 시간에 포함합니다. Qt 이벤트 처리가 지연되어 저장 시점이 늦어져도 마감 시각 이후 수신·표시된 영상은 제외합니다. 프레임이 없으면 빈 결과를 저장하고 FPS는 `null`입니다. 저장 실패 시 설정창의 `결과 저장`으로 재시도할 수 있습니다.

## 메인 앱과의 일치 범위

- 기존 개발용 `FramePerformanceWindow`를 상속하지 않습니다. 통계 도크 추가, 연습 화면으로 강제 이동, 영상 최소 크기 변경, 1280×900 강제 리사이즈를 제거했습니다.
- 실제 앱의 `MainWindow.update_frame()`을 그대로 호출합니다. 카메라·손 감지·추적·AR 그리기 코드를 별도로 복제하거나 변경하지 않습니다.
- 측정 중에는 프레임별 숫자 기록 추가, Qt paint 시각 기록, 1초 간격 종료·남은 시간 확인만 합니다. 전체 기록 순회, 백분위수 계산, 소스 해시 계산, 파일 저장은 수집 종료 후 수행합니다.
- 측정되지 않는 대기 상태에서는 프레임 기록을 모으지 않고 타이머도 실행하지 않습니다. 완료된 결과도 반복 집계하지 않습니다.
- 시간 기록과 이벤트 관찰에는 작은 추가 비용이 있으므로 무계측 실행과 성능이 완전히 같다고 보장하지 않습니다. 창 제목 갱신도 추가 작업입니다. 동일한 장비·창 크기·장면·연습 모드로 비교하세요.
- 새 결과에는 `measurement_profile: main_window_deferred_summary_v1`, `live_statistics: false`, 시작·종료 영상 크기, 창 크기, 화면 배율이 기록됩니다. **이전 통계 도크 방식의 결과와는 측정 조건이 다르므로 직접적인 개선율 비교에 사용하지 마세요.**

## 결과 파일

기본 저장 위치는 `benchmark/results/screen/fps-날짜-시각/`입니다. `--output-dir`로 변경할 수 있습니다. 결과 폴더는 Git에서 제외합니다.

- `summary.json`: 전체·추적 상태별 지표, 표본 수, 정의, 측정 시간·종료 상태, 실행 조건.
- `frames.csv`: 프레임별 시각과 처리 시간. 손 감지 시간(`hand_mask_ms`), 추적·그리기 시간(`tracking_ms`), 최근 재탐색 시간과 진행 여부도 포함합니다. 영상·오디오를 저장하지 않습니다.
- `report.md`: 보고서에 옮길 수 있는 지표 표.

## 지표 정의

| 지표 | 계산 및 해석 | 방향 |
|---|---|---|
| 화면 FPS | 유효한 새 영상 표시 간격 수 / 간격 합(초). 순간 FPS 평균이 아님 | 높을수록 좋음 |
| 프레임 간격 중앙값·p95·p99·최댓값 | 연속된 새 영상의 Qt paint 이벤트 진입 시각 차이 | 낮을수록 좋음 |
| 긴 프레임 비율 | 50ms 초과 간격 수 / 전체 유효 간격 수 × 100 | 낮을수록 좋음 |
| 멈춤 간격 수 | 100ms 초과 간격 수. 긴 프레임 수의 부분집합 | 같은 측정 시간에서 낮을수록 좋음 |
| 입력→화면 지연 중앙값·p95 | 카메라 `read()` 반환부터 해당 영상의 Qt paint 이벤트 진입까지 | 낮을수록 좋음 |
| 처리 시간 p95 | 수신한 영상의 워커 처리 시간, 미표시 영상 포함 | 병목 진단용 |
| UI 대기 p95 | 워커 emit부터 UI 슬롯 수신까지 | 병목 진단용 |

p95는 표본의 95%가 해당 값 이하임을 뜻하며 NumPy 기본 선형 보간을 사용합니다. 50/100ms는 진단 기준이며 보편적인 합격선이 아닙니다.

## 반복 실험

같은 컴퓨터·전원 모드·카메라·조명·영상 해상도·창 크기·모델·악보·연습 모드를 사용합니다. 맞추기 전 10초 → 정상 추적 30초 → 손 가림·이동 20초 → 화면 이탈·복귀 10초를 각각 별도 측정할 수 있습니다. 각 조건을 3회 이상 반복하고, 버전 비교 시 실행 순서를 번갈아 배치하세요. `--label`로 버전·동작·반복 번호를 남깁니다.

추적 상태별 표는 알고리즘 상태에 따른 자동 분류입니다. 손 가림 등의 실험 동작 라벨과 같지 않습니다. 앱 전체 연습 성능을 평가하려면 실제 연습 모드와 마이크 사용 여부도 동일하게 맞추세요.

## 해석상의 제한

- 화면 FPS는 새 영상의 Qt paint 이벤트 빈도입니다. 모니터 주사율이나 물리적 화면 출력 완료 FPS가 아닙니다. 동일 영상의 재그리기는 세지 않습니다.
- 입력→화면 지연은 노출·카메라 내부 버퍼·paint 실행 시간·물리적 화면 출력 시간을 포함하지 않습니다.
- 첫 표시 프레임에는 간격이 없고, 구간별 표는 서로 다른 추적 상태 사이의 간격을 제외합니다. FPS의 유효 간격 합은 지정 시간보다 짧을 수 있습니다.
- 마지막 표시 이후 아직 끝나지 않은 멈춤은 간격 통계에 포함되지 않습니다. 종료 시점의 `pending_paint_gap_ms`로 따로 보존합니다.
- 영상 창을 가리거나 최소화하면 Qt의 갱신 조건이 달라집니다. 측정 중 창을 보이게 유지하세요.
- `—`/`null`은 표본 부족 또는 측정 불가입니다. 적은 표본의 p99를 안정적인 평가값으로 간주하지 마세요.
- 조명·발열·전원 모드·백그라운드 부하·연주 동작은 자동 통제되지 않습니다. 실제 카메라 성능은 직접 측정해야 하며 자동 테스트 결과로 대신할 수 없습니다.
